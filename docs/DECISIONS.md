# Decisions Log

One line per decision: the choice + a one-line reason. Newest at the bottom.

## M0 - Foundation

- **Pin `phaser@4.2.1` exactly** - latest stable Phaser 4; mandated exact pin for reproducible builds.
- **Use known-good stable toolchain over bleeding edge** - `typescript@5.9.3`, `vite@7.3.6`, `vitest@3.2.7`, `eslint@9.37.0`, `prettier@3.6.2`, `@playwright/test@1.56.0`, `typescript-eslint@8.46.0`; the bleeding-edge set (TS 7.x, Vite 8.x, Vitest 5.x, ESLint 10.x) has no matching `typescript-eslint` release and risks parser/config breakage this early. Recorded for reproducibility.
- **`tsx@4.20.6` for running TS build scripts** - lets `gen:trig` and the wired `record:solutions`/`gen:icons` scripts run TypeScript directly without a separate build step.
- **PRNG = sfc32 seeded via mulberry32, state in sim state** - large well-mixed state, trivially serializable as 4x uint32, and no module-level RNG so replays/forks stay bit-exact.
- **Angles as "brads" (4096 per turn, `ANGLE_BITS=12`)** - power-of-two turn lets the sim wrap angles with a bitmask (no float remainder), and 4096 steps give ~0.088deg resolution.
- **Trig tables scaled by 2^15 (`TRIG_ONE=32768`)** - fits signed 16-bit range with headroom, keeps fixed-point multiplies in the 32-bit integer lane.
- **Cosine reuses the sine table with a quarter-turn offset** - one committed table instead of two; halves generated data.
- **`atan2` via minimax rational approximation (+ - \* / only)** - deterministic and dependency-free; error is a few brads, well within aiming needs.
- **FNV-1a hash quantizes numbers to a 1/1024 grid, sorts object keys** - makes the determinism fingerprint invariant to float noise and serialization/key order.
- **Fixed-timestep runner lives in `src/game`, not `src/sim`** - it reads wall-clock deltas (non-deterministic), which the pure sim must never touch.
- **Runner caps at 5 ticks/frame and drops backlog (slow down, never skip)** - preserves determinism under load instead of fast-forwarding.
- **Inline SVG data-URI favicon in `index.html`** - avoids a `/favicon.ico` 404 that would otherwise register as a console error in the E2E boot gate; real asset, not a stub.
- **Playwright points at the pre-installed Chromium at `/opt/playwright/chromium-1232` via `executablePath`** - the bundled revision differs from the one `@playwright/test@1.56` would auto-download; using the local binary avoids a network fetch and version mismatch. Overridable via `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.
- **`record:solutions` / `gen:icons` are wired but no-op today** - their inputs (levels, brand mark, PWA manifest) do not exist until later milestones; they exit 0 with an explicit "nothing to do" message rather than shipping fake output.

## M1 - Vertical slice + frozen sim contracts

- **Class stats the sim reads live in `src/sim/classes.ts`; presentation-only facts in `src/content/classes.ts`** - the pure sim must be self-contained and deterministic, so numeric kit data cannot depend on the content layer; colour/name/sound/silhouette are render-only and stay in content.
- **World positions are plain JS numbers in units (not fixed-point integers)** - only `+ - * / sqrt` are used on them and the FNV-1a hash quantizes to 1/1024, so double arithmetic stays bit-reproducible without a manual fixed-point layer; simpler and less error-prone.
- **Transient scratch (spatial hash, echo-input buffer, boss pattern ref) is module-level and NOT hashed** - it is fully derived from hashed state + deterministic inputs each tick, so keeping it out of `SimState` avoids polluting the fingerprint while staying deterministic.
- **`LevelRunner` is pure and lives in `src/sim`** - the whole time-loop (recordings, live/echo routing, restart-each-loop, win/fail, stars) is deterministic orchestration with no wall clock, so it belongs in the pure layer; the fixed-timestep runner in `src/game` only converts real time to ticks.
- **Healing threat is credited to the healer's own threat entry** - the rule ("credited to every enemy in combat") has one enemy in M1; attributing it to the healer makes the boss aggro the pocket healer, which is the intended tactical pressure and keeps the tie-break rule meaningful.
- **Boss HP tuned to 1300; solution plan Guardian -> Medic -> Ranger** - boss HP resets each loop, so the win must come from enough fighters in ONE loop; 1300 lets the final loop (2 echoes + live Ranger) win while loops 0-1 cannot, showcasing all three classes and the "team builds up" fantasy. 2-star win (win + >=1 echo alive).
- **Boss charge attack gated to phase 2 (<=50% HP)** - gives the fight a readable escalation past the phase-1 threshold without adding mechanics the M1 classes cannot answer.
- **Dev hook exposes `fastForward(maxTicks)`** - e2e must drive three 20s loops; stepping the runner directly (deterministic, no wall clock) keeps the test fast while still going through the real live/echo input pipeline.
- **Victory stars drawn as graphics, not `★` glyphs** - the headless Chromium system font renders the star glyph as tofu boxes; polygon stars render reliably everywhere.
- **`createSimState(seed)` kept as a minimal built-in arena** - generic determinism/runner tests want "a state that evolves deterministically" without importing the content layer; it builds a tiny self-contained boss+Guardian arena.

## M2 - Full core

- **`ClassId` extended additively with `pyromancer`/`rogue`/`engineer`/`avatar`** - a new enum member is an allowed extension of the frozen M1 contract; existing members and semantics are untouched.
- **Paradox verdicts (`paradox`, `paradoxTelegraph`, `divergedTicks`) live in `SimState` and are hashed; the recordings that feed detection are injected as transient scratch via `setEchoRecordings`** - the verdict is deterministic gameplay state, but the recorded path/anchors are derived data (like echo inputs) so they stay out of the fingerprint, mirroring the M1 transient-scratch rule.
- **Interactables carry a stable `defIndex` (level-list order), separate from the per-loop `id`** - a recorded anchor must reference the same conceptual object across loops even though entity ids are re-allocated each loop.
- **A paradox echo becomes `team: 'enemy'` but is still processed in the player-unit act loop (guarded by `u.paradox`)** - it must count its telegraph down and run its hostile kit; skipping it by team alone froze the telegraph. It is excluded from boss threat targeting yet attacks everyone incl. the boss.
- **Support inversion is hard-coded per class in `doParadoxPrimary`/`doParadoxSkill`** - heal->drain, Sanctuary->damage zone, turret->hostileToAll; the cleanest deterministic mapping without adding inversion flags to every ability.
- **Paradox echo does nothing during its 0.5s glitch telegraph** - matches "0.5s glitch telegraph then turns hostile"; simpler and more readable than letting it keep acting as its old kit mid-glitch.
- **Efficiency star = win with <=1 rewrite OR early victory** - wires the rewrite count into the star rating (contract 3.5) while preserving the M1 early-victory star.
- **Rewrite allowed at any between-loops gate (class-pick or decision), not only after all slots recorded** - faithful to contract 3.5 ("after ANY loop the player may re-record any existing slot"); a `resumeSlot` restores the interrupted slot after a mid-sequence rewrite.
- **Pre-sim lives in `src/sim/presim.ts` (pure) and is imported by both the Web Worker and the main-thread client** - guarantees the worker runs the IDENTICAL engine-free sim; a Node test asserts its per-tick hashes match a hand-driven main-thread loop (contract 3.7 parity).
- **Pre-sim client falls back to main-thread `runPreSim` when `Worker` is unavailable or errors** - keeps the planning phase working in headless/software contexts; the result is bit-identical either way.
- **Phaser 4 Filters attached to the world layer game object (`obj.enableFilters()`), not the camera** - in Phaser 4 the `filters` component lives on game objects; Glow gives the neon bloom and Barrel+ColorMatrix drive the chromatic/VHS rewind. Wrapped in try/catch so a software renderer degrades gracefully.
- **VFX are pooled with hard caps (220 particles, 40 damage numbers)** - honours the "object pools, no per-tick allocations, particle caps" rule; shake/flash/slow-mo are render-only and never touch sim ticks.
- **Procedural WebAudio engine, unlocked on first tap, one gain-controlled layer per class** - no audio assets; layers gate on echo life and a paradox detunes+quietens its layer (bitcrush-adjacent via detune + reduced gain); every action fires a synthesized SFX.
- **New showcase level `arena-02` (7 slots, boss HP 9000, 2 shard interactables)** - HP tuned so the squad cannot burst the boss before the Final Avatar's loop, making Convergence the intended finisher; two shards let a deliberate double-grab break an anchor (paradox) and demonstrate the full M2 flow.
- **Emoji glyphs replaced with ASCII in HUD/overlays** - the headless Chromium system font renders `★`/`⚠`/arrows as tofu; stars use polygon graphics and labels use ASCII (`X`, `>`, `<<`).

## M3 - Content & meta (in progress)

- **Meta layer split into pure modules (`economy`, `cosmetics`, `monetization`, `save`) + impure `platform/storage`** - the reward math, catalog, migrations and mutations are all pure and unit-tested; only localStorage/base64 I/O is impure, so the whole progression system is deterministic and testable without a browser.
- **Save schema at version 3 with a linear migration chain (v1->v2->v3)** - each migration is a pure function; `migrate()` walks forward then `normalize()` fills defaults + clamps, so any old or partial save loads to a valid current save. Real, exercised migrations (mastery/seenIntro added in v2; sound-bool -> three volume sliders + assistMode + replaySeq in v3), not placeholders.
- **Export/import save code = `SQ1-` + base64(JSON)** - simple, versioned, and migrates on import; base64 helpers work in both Node and browser (TextEncoder/btoa with a Buffer fallback) so tests and runtime share one path.
- **Monetization adapter ships as a `NoopMonetizationAdapter`, flags off by default, product kind limited to `cosmetic`** - structurally enforces the hard rules (no pay-to-win/loot-box/real-money): there is no consumable-currency or power product kind in the interface at all, and the default build reports everything unavailable.
- **First-clear shard bonus (+25) rather than scaling repeat rewards** - discourages grinding one level as the shard farm while keeping first clears generous; repeat replays still pay out the base amount.
- **Fonts subsetted with fontTools to the exact glyphs the i18n tables use (+ full ASCII)** - Latin 10 KB + Devanagari 37 KB = ~47 KB total, far under budget, and a coverage check asserts every required codepoint is present so neither script shows tofu. `npm run gen:fonts` downloads the upstream OFL TTFs and regenerates the WOFF2 subsets; OFL.txt + CREDITS attribute them.
- **i18n: every string is a key; `t()` returns the key itself for unknowns (loud, not blank); locales must match key sets exactly (test-enforced)** - a missing Hindi string is caught by CI rather than silently falling back, and a source scan enforces no hard-coded user-facing text in `src/ui`.
- **Campaign authored as a presentation/progression wrapper (`CampaignLevel`) around the frozen `LevelDef`** - worlds own palette/hazard/musical-scale/boss-intro; the sim never reads campaign metadata, so content theming and the unlock ramp evolve without touching the frozen contract.
- **Boss HP tuned via `scripts/calibrate.ts` (binary search of the beatable ceiling per slot count) to ~80-90% of ceiling** - guarantees the reference plan wins with >= 1 star (recorded solutions all reach 3 stars) while keeping the final loop tense; re-run after any balance change.
- **Four boss archetypes are distinct pattern scripts reusing the frozen slam/cone/charge shapes with phase gating (`maxHpFraction`)** - Pendulum Knight, Mirage Djinn, Stasis Wyrm and The Unwinder differ in timing/reach/phase-density, so the boss-HP-resets-per-loop discovery curve is real without new sim primitives.
- **Objective types authored as campaign metadata over the existing boss+interactable sim** - `boss` is fully simulated; `heist`/`survive`/`build` are tagged for presentation + tutorial panels and use shard/lever interactables where the current sim supports them. (Superseded below: the dedicated SIM mechanics landed in the M3 continuation.)

## M3 (continuation) - enemy roster, objectives, UI suite, FTE, e2e

- **Minions live in `state.units` with `kind:'minion'`, `team:'enemy'`, spawned from a module-level `currentMinions` schedule (like `currentPattern`)** - reuses the frozen projectile/threat/paradox pipeline (player ranged/AoE already damages any enemy-team unit) instead of a parallel array; the schedule is deterministic content data set once per loop by the runner + presim, so it stays out of the hashed state while spawned units are hashed. `LevelRunner.setLevelScripts()` and `runPreSim` both install it so worker/main-thread parity holds.
- **Six minion archetypes as a generic deterministic AI switch on `enemyKind`** - chaser/shielded (telegraphed melee), caster (stand-off telegraphed bolt), bomber (charge + telegraphed AoE, self-destruct), healer (flees, heals wounded enemies incl. boss), splitter (spawns 2 gen-1 children on death). Each has a visible wind-up (`attackTelegraph`/`telegraphTotal`) for fair telegraphs.
- **Objective win-conditions added to `LevelDef.objective` + `SimState.objective`, evaluated in a new `evaluateOutcome()`** - `boss` (default, unchanged) wins on boss death; `survive` wins at loop end if every protected core is intact (a destroyed core fails immediately); `heist` wins when every core reaches its goal AND every gating door is open; `build` wins when every build pad is complete. Additive: omitting the field keeps M1/M2 boss levels byte-identical.
- **Objective mechanics reuse the `Interactable` primitive additively (new kinds `plate`/`door`/`buildpad`/`core`)** - pressure plates react to live-unit presence each tick; doors open while their linked plate/lever is active; build pads fill while stood on; heist cores are grabbed via the existing Interact button and ferried by their carrier (echo or live). No new movement statuses, preserving the frozen 3.2 invariants; doors gate the heist win rather than physically colliding (keeps player-team non-collision intact).
- **Objective levels solved by role-based bots keyed off slot index** - the lowest slot holds a pressure plate while the highest slots ferry cores; build bots spread across pads; survive bots fight at a standoff. Because roles map to slots, the recorded echoes cooperate across loops exactly as a human squad would. All 19 levels re-recorded via `npm run record:solutions` and the solvability gate re-asserted (>= 2 stars each).
- **UI menu suite built as Phaser scenes in `src/ui` sharing a `ui-kit` (localized `label()`, vector `drawStars`/`starPath`, `button`, `panel`)** - stars/icons are drawn as polygons (headless Chromium renders star/emoji glyphs as tofu) and all text flows through `t()` with `fontFamilyForCurrentLocale()`; the i18n no-hard-coded-strings scan enforces this now that `src/ui` is populated.
- **World map is a compact per-world row of level nodes** - a plain list overflowed the 390x844 viewport under the Back button; a node grid (rounded square + star pips + lock) fits all 19 levels + 5 worlds on every target viewport under the FIT scale.
- **Settings wired to `SaveSettings` through a `save-context` singleton that applies on every change** - locale/font, the three volume buses (new `AudioEngine.setVolumes`), haptics (`setHapticsEnabled`) and text scale take effect immediately; Assist Mode + colour-blind identity (per-class shape+number in the render layer) are save toggles. Volume sliders are stepped (0.25) for deterministic, testable interaction.
- **First-time experience is a self-contained scripted encounter in its own scene** - it runs a tiny training-golem arena through the pure sim: loop 1 alone falls short, a rewind flourish plays, then loop 2 replays loop-1 inputs as an echo fighting beside you and the golem falls - the "aha" lands in ~12 s (< 60). `SaveGame.seenIntro` gates it; `?fte=1` force-replays it for screenshots.
- **Boot: FTE auto-starts as scene[0] and self-routes to the title when `seenIntro` is set (or a `?scene=`/`?level=` deep-link is present)** - no separate boot scene; deep-links stop the FTE/title and start the target once so exactly one scene is ever active (a lingering title over the GameScene was the root cause of an early e2e flake).
- **Two dev hooks for e2e: gameplay `window.__SQUAD` (tick-exact input) and menu `window.__SQUAD_UI` (active-scene readout + switch)** - the boot->FTE->Tutorial-1->results flow drives the sim through `__SQUAD` and navigates menus through `__SQUAD_UI`; a separate test uses real keyboard + touch events. Multi-viewport screenshots (390x844/844x390/768x1024/1920x1080) of every screen are captured + inspected (FIT letterboxes the one 390x844 layout).
- **GameScene launched from the UI hands off to a localized `ResultsScene`** - which records the outcome into the save (best stars, currency, XP, mastery, top-20 replay) and offers Next/Retry/Quit; the M2 in-scene result screen is kept only for the standalone `?scene=game` showcase path.
- **E2E runs serialized (`fullyParallel: false`, `workers: 1`, `retries: 2`)** - the game is a heavy WebGL/canvas app served by a single `vite preview` instance, so parallel browser contexts share one render loop; the long multi-viewport screenshot spec starved the tick-exact Tutorial-1 flow and its 15s scene-transition waits timed out under load (product logic was fine - it passed in isolation and at `--workers=1`). Serializing gives each spec the render loop to itself; the two retries are defence-in-depth against residual timing jitter. The contention-sensitive `waitForFunction` scene-transition timeouts in `m3-flow.spec.ts` (waiting for `ui-title`/`ui-levelintro`/`ui-results`/`ui-worldmap` etc.) were also raised to a comfortable margin. No assertions were weakened - the suite still finishes Tutorial 1, reaches localized results, exercises real keyboard+touch, captures every multi-viewport screenshot, and asserts zero console/page errors.

## M4 - Modes & sharing

- **`SIM_VERSION` (src/sim/version.ts) + a content hash (src/content/content-hash.ts) are the replay-compatibility fingerprint** - the sim version pins the `step()`/entity/RLE rules; the content hash is FNV-1a (the same `hashState`) over the *sim-facing* fields of every campaign `LevelDef` (arena/loop/slots/spawns/boss+pattern/interactables/minions/echoHpScale), deliberately excluding presentation metadata (i18n keys, story, unlocks) so re-theming a level never invalidates existing codes. Both travel in every replay code; the decoder refuses a mismatch (typed `version-mismatch`) rather than replaying incompatible data.
- **Replay code = base64url of a tight binary payload {magic, format, simVersion, contentHash, seed, score, wonOnSlot, levelId, per-slot(classByte + RLE inputs)}** - reuses the frozen `encodeInputs`/`decodeInputs` RLE for the per-slot streams; a custom base64url codec (no Buffer/btoa) keeps encode/decode PURE so it runs in Node, browser and Worker identically. `decodeReplayCode` returns a discriminated union (`ok` / `malformed` / `version-mismatch`) so no caller can accidentally play a bad code.
- **`/#r=<code>` replays by driving the frozen `LevelRunner` with the decoded per-slot frames as the live scripted source, auto-picking each recorded class** - playback goes through the exact same `step()` path as live/echo input, so it is bit-identical (proven by `tests/determinism/replay-code-playback.test.ts`: replay reproduces the winning slot, stars, and the final `hashState`). "Beat this run" just starts the same level fresh (no replay) so the player is scored against the shared run's score.
- **Daily Paradox seed + selection + score are all computed OUTSIDE the sim (src/content/daily.ts)** - `dateKeyOf(new Date())` is the only Date read and it lives in content, not the sim; an LCG stepped from the FNV date-seed picks one eligible boss level + two distinct modifiers. Score = base + time-in-loop bonus + echoes-alive + early-victory - rewrite penalty. Modifiers (src/content/modifiers.ts) are typed data that transform a cloned `LevelDef` deterministically (enraged/tanky/swift boss edit the pattern/HP/speed; five-slots trims slotCount+spawns; short-loop trims loopLength; glass-echoes sets the new additive `LevelDef.echoHpScale`). A single-attempt rule: a surviving boss ends the daily (no rewrite loop).
- **`LevelDef.echoHpScale` is a new ADDITIVE optional field applied once at spawn in `createLevelState`** - lets the glass-echoes modifier halve starting HP without touching the frozen step semantics; defaults to 1 so every existing level hashes/plays identically. Included in the content hash so it is part of the replay fingerprint.
- **Time Chess is a self-contained PURE duel sim (src/content/time-chess*.ts), NOT the boss sim** - a symmetric two-team, control-zone ruleset is a different game, so building it separately keeps the frozen `step()` contract untouched. It uses only the sim's committed integer trig + the InputFrame type; all state is plain numbers so it is deterministic and reproducible by construction. 5 loops x 15 s; both sides record simultaneously while prior loops of both sides replay; score = zone-ticks + units-alive*100; unique class per loop per side, no Avatar.
- **The Time Chess AI bot is a seeded, engine-free decision function (`tcAiFrame`)** - given (seed, difficulty, state, unit, tick) it returns an InputFrame using integer trig + a tiny `mix()` hash for deterministic jitter (no Math.random). Same seed+difficulty => bit-identical play (proven in `tests/unit/time-chess.test.ts`); difficulties tune zone-bias, jitter and attack range. The vs-AI seed is fixed per difficulty (101/202/303) so a given difficulty always plays the same duel.
- **Clip export lives in src/platform/share.ts behind capability probes** - `MediaRecorder.isTypeSupported` picks the mimeType (vp9/vp8/webm/mp4 fallbacks); `canvas.captureStream(30)` is the video source; game audio is mixed via `AudioEngine.getAudioGraph()` -> `createMediaStreamDestination()`; a watermark is stamped. Sharing uses the Web Share API (files) with `navigator.canShare` guard and a download fallback; where MediaRecorder/captureStream are unavailable (headless), it degrades to a single-frame watermarked PNG (`png-fallback`). The e2e asserts a produced blob OR the graceful fallback.
- **PNG result cards render on an offscreen 2D canvas** (victories + Daily results) with vector stars (no glyph tofu), stat rows, seed and watermark; shared/downloaded via the same `shareOrDownload` path.
- **Replays screen gains an HTML `<input>` overlay positioned over the FIT-scaled canvas for pasting codes** - Phaser has no native text field; the input is absolutely positioned by mapping game-space coords through the canvas bounding box, and torn down on scene shutdown. Load & Play (deterministic playback), Beat This Run, and tapping a stored row all route through the shared decode -> clear-message-on-mismatch path.
- **Dev/e2e hooks added additively** - `window.__SQUAD_TC` (start/fast-forward a vs-AI match + read scores), `window.__SQUAD_DAILY` (run the daily headlessly to a scored result card), `window.__SQUAD_SHARE` (exportClip/resultCardSize for capability verification) and `window.__SQUAD_REPLAY` (build a winning code headlessly). All are dev-only, touch only window, and never affect live play; they let the M4 e2e verify clip export, `/#r=` playback, Daily and Time Chess deterministically without wall-clock gameplay loops.
- **Save schema bumped to v4 (adds `dailyBest` per date key) with a v3->v4 migration** - pure, exercised, defaulted in `normalize()`; the local Daily best is kept per date via `recordDailyResult`.

## M5 - Ship quality

- **Dev tools gated on a compile-time `__DEV_TOOLS__` Vite define, not a runtime flag** - `if (__DEV_TOOLS__)` folds to `if (false)` in the release build so Rollup dead-code-eliminates every dev/e2e hook (`window.__SQUAD*`), the debug overlay and the perf/parity hooks AND their imports; a runtime flag would leave the code (and its `__SQUAD` globals) in the shipped bundle. Verified absent by `scripts/check-prod-bundle.ts`.
- **Default `npm run build` keeps dev tools ON; the shipped bundle is `npm run build:release` (`VITE_RELEASE=1`)** - the Playwright e2e suite runs against `vite preview` of the DEFAULT build and drives the sim through the `__SQUAD*` hooks, so stripping them from the default build would break the gate. The release/Playables builds strip them; `check:prod` proves the shipped artifact is clean.
- **Hand-rolled offline service worker generated by a tiny Vite plugin, not vite-plugin-pwa/Workbox** - the plugin derives the precache list from the real build output (JS/CSS/fonts/icons/manifest/index.html, source maps excluded) and emits a cache-first `sw.js`; zero extra runtime dependencies, full control over the "zero network call at play time" guarantee, and no Workbox runtime shipped in the bundle.
- **Cache-first SW strategy with same-origin-only network fallback** - after install the game serves entirely from cache (true offline PWA); the fetch fallback is same-origin only and never reaches a third party, honouring the Playables no-external-call rule. Verified by `e2e/offline.spec.ts` (zero external requests + full offline reload).
- **PWA icons generated from an SVG brand mark via headless Chromium (`npm run gen:icons`)** - the M0 no-op is now real: `scripts/gen-icons.ts` rasterises a "time-loop lens" mark (ring + core + three orbiting echo dots, matching the favicon) at 192/512/maskable-512/apple-180 into `public/icons/`; maskable variant adds the 20% safe-zone padding. Committed so the offline build never fetches them.
- **Auto resolution scaling reduces the canvas backing-store resolution (CSS size fixed), not a Phaser zoom** - lowering the drawing-buffer size is what actually cuts GPU fill-rate cost; the browser upscales the smaller buffer. Logical/world coords and the fixed-60 Hz sim are untouched, so input mapping and determinism are unaffected. Triggers below 50 FPS, recovers above 58, 1.5 s cooldown.
- **YouTube Playables adapter behind the `__PLAYABLES__` define, OFF by default, engages only when `ytgame.IN_PLAYABLES_ENV === true`** - `firstFrameReady`/`gameReady`/`setSavedData`/`getSavedData`/`sendScore` are forwarded to the host-injected `ytgame` global; every path is a safe no-op otherwise, and the adapter NEVER fetches a script or hits a URL (the host injects the SDK), so it makes zero external calls. Built via `npm run build:playables`.
- **No balance-number changes in M5; solution replays NOT re-recorded** - the full level-solution gate (all 19 campaign levels win with >= 2 stars, live + via recorded replay: 41 assertions) was already green and stable from M3/M4, and there are no crashes/soft-locks (unit + determinism + e2e suites green). Re-tuning well-balanced, frozen-content numbers would risk destabilising a proven gate for no gameplay benefit, so the bug-bash conclusion is "already balanced"; because nothing changed, re-recording was unnecessary. (The `record:solutions` + `calibrate` pipeline remains available for any future change.)
- **Node-vs-browser hash parity uses one PURE harness (`src/content/parity.ts`) run in both places** - a committed fixture (`tests/determinism/parity-fixture.json`, generated by `scripts/gen-parity-fixture.ts`) holds the reference final + stride-sampled per-tick hashes for a fixed level+plan; the Node test (`parity-node.test.ts`) reproduces it and the e2e (`parity.spec.ts`) runs the identical harness in real Chromium via `window.__SQUAD_DET` and asserts equal hashes - closing determinism gate 2.
- **Parity harness level = `w1-boss` with plan guardian/medic/ranger/pyromancer/avatar** - a 5-slot boss level exercises the full multi-echo pipeline (Avatar is forced last per the last-slot-only rule); the run is deterministic regardless of win/loss, which is all the parity gate needs.
- **Capacitor Android wrapper loads the BUNDLED `dist/` (no `server.url`)** - the native shell ships the same offline bundle as the PWA, so the app runs with zero network calls inside the APK too. `capacitor.config.ts` is validated by `npx cap copy`; a full APK build needs the Android SDK/Gradle (documented in the README) which is not installed in this sandbox, so we verify config validity rather than building an APK here. `android/` is git-ignored (scaffolded locally via `npx cap add android`).
- **`chunkSizeWarningLimit` raised to 1500 kB** - Phaser is an intentional ~1.3 MB vendor chunk, well under the 5 MB initial-load budget; the M0 >500 kB warning is resolved by isolating the engine, not by shrinking Phaser, so the warning limit is set past the deliberate chunk to keep build output clean.
- **Source maps only in the dev/e2e build, omitted from `build:release`** - keeps the shipped bundle lean and avoids precaching maps that are never fetched at play time.
- **Capacitor 8.5.2 (core/cli/android) pinned via `npm install`** - latest stable at build time; recorded for reproducibility.

## Visual Overhaul (FEAT-001 - frozen visual-kit contract)

The game shipped functionally complete but visually flat ("solid dark rounded rect + 2px border" buttons, single-fill backgrounds, plain Noto title). FEAT-001 establishes and FREEZES a premium visual kit (typography + palette + Filters bloom infra + upgraded shared ui-kit widgets) BEFORE any per-scene work, mirroring how M1 froze the sim contracts. All changes are render/presentation-layer only; `src/sim/**` is byte-identical and every determinism/parity/solution test still passes.

- **Display font: Orbitron (OFL-1.1), subsetted + self-hosted** - a geometric sci-fi face for Latin titles/headlines. The upstream variable `Orbitron[wght].ttf` is instanced to a single bold weight (700) and subsetted to printable-ASCII + common symbols in `scripts/subset-fonts.py`, producing a ~4.8 KB `public/fonts/Orbitron-subset.woff2`. It is declared via `@font-face` in `index.html`, loaded through `FONT_FAMILIES`/`ensureFontsLoaded`, and selected by the new `fontFamilyForDisplay()` helper. For the Hindi locale `fontFamilyForDisplay()` gracefully falls back to Noto Sans Devanagari (Orbitron has no Devanagari glyphs), so Hindi headings keep their locale font and never tofu (verified by screenshot). Attributed in `docs/CREDITS.md` + `public/fonts/OFL.txt`. The 400 KB font guard was NOT raised (total fonts ~52 KB).
- **Palette: gradient-ready design tokens, not a flat COLORS map** - `src/game/render/colors.ts` keeps all existing flat `COLORS` keys and `lerpColor` for compatibility, and adds `GRADIENTS` (top/bottom stop pairs for lit-volume fills), `GLOWS` (neon accent + shadow colours), `TINTS` (highlight/shadow for bevels), plus shared helpers (`gradientBands`, `lighten`, `darken`). The ui-kit and GameScene share these tokens so depth reads consistently.
- **Effects: Phaser 4 native unified Filters, NO 3D library** - `src/game/render/filters.ts` keeps the existing Glow/Barrel/ColorMatrix rewind path and adds a real bloom (tuned `addGlow` + a soft `addBlur` pass) plus an optional cinematic `addVignette`, with a tunable `setBloom(intensity)` so the accessibility "reduced flashing" setting can scale it down (or to 0). Every Filter API used (`addGlow`/`addBlur`/`addVignette`/`addBarrel`/`addColorMatrix`) was verified against `node_modules/phaser/types/phaser.d.ts`, and the whole install is try/catch-guarded to degrade on software renderers. A background Three.js/PixiJS depth layer was EVALUATED and DECLINED: native Filters already deliver bloom/glow/vignette within the 60 fps/4x-throttle target, and adding a 3D engine would spend a large chunk of the ~3.4 MB initial-load headroom (Three.js alone is well over 1 MB) for an effect the native pipeline covers - not worth the bundle/perf cost for a mobile offline PWA.
- **ui-kit: upgraded look via OPTIONAL opts, public API frozen** - `button()` now renders a vertical gradient fill, soft drop shadow, inner highlight bevel, accent-glow halo and a hover/press scale micro-animation (honoring reduced-motion); `panel()` is a glass/gradient surface with soft shadow, inner border and an optional accent edge; `label()` gained a `display` option (Orbitron headline face) and a `glow` option; filled stars get a gold gradient + soft glow. The exported symbols (`UI_COLORS`, `LabelOpts`, `Button`, `label`, `button`, `drawStars`, `starPath`, `panel`), parameter order, the `Button` shape (`{container, setEnabled, setLabel}`) and every `name:` identifier used by e2e/showcase are UNCHANGED - all new look is additive. Upgrading these shared widgets lifts every menu at once (the force-multiplier).
- **Shared animated backdrop: `src/game/render/backdrop.ts` with a frozen create/update/destroy API** - `createBackdrop(scene, opts)` returns `{update(dtMs), resize(w,h), setDepth(d), destroy()}`. It procedurally draws (Phaser Graphics, no image assets, no network) a deep gradient wash + parallax starfield + a slowly rotating neon clockwork ring + an 8-fold rangoli/jaali lattice ("neon clockwork + Indian geometric" motif). It honors reduced-motion by rendering one static frame and no-oping `update()` (the static fallback), stays cheap (modest star count, lightweight stroked lattice), and sits at depth -100 so scene content layers above it. TitleScene adopts it now; FEAT-002/003 adopt the same API uniformly.
- **Frozen visual-kit API surface (contract for FEAT-002/003):** `colors.ts` -> `COLORS`, `GRADIENTS`, `GLOWS`, `TINTS`, `lerpColor`, `gradientBands`, `lighten`, `darken`; `filters.ts` -> `installFilters(target, opts?)` returning `SceneFilters` with `glow/barrel/colorMatrix/bloom/vignette`, `setRewind(active,intensity)`, `setBloom(intensity)`, `update(rewindActive)`; `ui-kit.ts` -> frozen signatures above; `backdrop.ts` -> `createBackdrop(scene, opts?)` returning `Backdrop`; `i18n/fonts.ts` -> `fontFamilyForDisplay()`.
- **Showcase capture serves `dist/` from an in-process Node http server (`scripts/showcase-static.mjs`), not `vite preview`** - in this sandbox a spawned `vite preview` listening server is SIGTERM-killed by the host, which blocks the `vite preview`-based showcase/e2e path. An in-process static server (same Node process as Playwright) is not killed and reproduces the same WebGL/Filters output, so visual before/after proof still works. Remember to run plain `npm run build` (dev tools ON, installs `window.__SQUAD_UI`) before capturing - `check:prod` runs `build:release` which strips the hook.
